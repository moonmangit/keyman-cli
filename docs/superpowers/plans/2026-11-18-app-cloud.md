# Keyman Cloud in the Desktop App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sign-in and sync for Keyman Cloud in the desktop app (`gui/`), with the same library code as the CLI.

**Architecture:** Small library changes make the cloud flows UI-friendly (no stdout, a cancel hook, structured results). In the app, each cloud action runs on a `std::thread`; a bridge `Prompt`/`Resolver` sends questions to the UI with `AppHandle::update` and waits on a one-time channel for the answer. New screens: Settings › Account, a first-use card, cloud dialogs, title-bar cloud icon and **Sync**, project link/unlink, sidebar marks, and a Sync results dialog.

**Tech Stack:** Rust; `keyman-cli` library (`src/cloud/`); desktop app on Rune (git dependency, toolchain 1.99.1 pinned in `gui/rust-toolchain.toml`, own Cargo workspace in `gui/`); `std::sync::mpsc` for the bridge.

**Spec:** `docs/superpowers/specs/2026-11-18-app-cloud-design.md` (and the cloud design `docs/superpowers/specs/2026-11-17-cloud-sync-design.md`).

## Global Constraints

- New user-facing text: ASD-STE100, in English and Thai through `i18n::t(en, th)` / `tf!`. Library error text stays English.
- The app does no network request before the user signs in or clicks a cloud action. App start uses local data only.
- A secret (password, recovery code, private key, variable value) never goes to a log, stdout, or a lasting clipboard entry. Copy uses the existing "kept out of clipboard history, then cleared" path.
- One cloud task at a time. Cloud tasks: sign in, recover, change password, sign out, loading the link picker, link, Sync, **Merge**, **Delete from cloud**. While one runs, all cloud buttons and **Unlink** are disabled.
- The window never freezes during a cloud action.
- A cancelled action leaves no half-done change. Cancel takes effect at the next question or in the browser wait; a running step finishes first, label "Cancelling…".
- The CLI output and behavior stay the same.
- Root crate CI must pass: `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`. The app must pass `cd gui && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`.

## Review Focus

1. The user closes the window while a background task waits for an answer (password dialog open). Expected: the thread ends with no change written; the app closes normally. Test: Task 2 `dropped_answer_cancels_the_question`.
2. The user double-clicks **Sync** or clicks **Link** during a sync. Expected: the second action does not start. Test: Task 2 `only_one_task_runs`.
3. The network is down when the user clicks **Sync**. Expected: one toast with the connect message, the master file and the links do not change, the app goes back to idle. Test: Task 5 `a_failed_task_returns_to_idle`.
4. The server rejects the saved sign-in. Expected: the app changes to signed out, shows the toast, opens Settings › Account. Test: Task 5 `rejected_sign_in_signs_out`.
5. The master file changes in the user's editor while Sync waits for a conflict answer. Expected: that project is listed in Sync results with the library's "The master file changed while Keyman worked…" reason, nothing written. Test: Task 5 `sync_results_list_needs_attention`.

  - Defined here, used by Task 5: `pub struct SyncSummary { pub updated: usize, pub added: Vec<String>, pub sent: usize, pub attention: Vec<Attention>, pub given: Vec<(String, String)>, pub warnings: Vec<String> }` and `pub enum Attention { Skipped { project: String, reason: String }, Stopped { project: String, conflicts: usize }, CloudIsNewer(String), CanMerge(String) }` (both `Debug, Clone, PartialEq`). ## Calls this plan makes (beyond the spec)

- `Prompt` gets default methods, so existing test prompts and the E2E `Answers` keep compiling.
- `sign_in_with_browser` takes the `Prompt` for the link and the cancel check (one parameter instead of two callbacks).
- The bridge is generic over a "post" closure so it is testable without a window.
- `cloud_prompt_done` lives in the app `Settings` (prefs), default `false`.
- Task 6's manual check is a stop point that needs the user.
